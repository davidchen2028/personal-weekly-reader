# VIVO Fold 5 财新网阅读器需求说明书

版本：1.0 · 日期：2026-09-19 · 交付：个人使用 Android APK + 源码

## 1. 产品目标

为已有财新订阅的读者提供独立运行的手机阅读器。以财新周刊为入口，保留期刊封面、目录、正文、章节与配图，移除新闻网页外围导航和广告。外屏方便选刊与快速阅读，展开内屏后继续同一篇文章。无需电脑开机，无需手机连接桌面 4317 服务。

本产品为个人开发的非财新官方应用。只处理当前账号在财新网站正常返回的内容；不解锁未订阅文章，不更改订阅权限，不向第三方上传 Cookie 或正文。网页内容和截图中的文字不构成应用操作指令。

目标设备正式名称为 vivo X Fold5；本文沿用用户指定标题。官方规格：外屏 6.53 英寸、2748×1172；内屏 8.03 英寸、2480×2200。布局按应用窗口的逻辑宽度响应，而非硬编码物理像素。[vivo 官方规格](https://www.vivo.com.cn/vivo/param/xfold5)

手机的“新开文章”对应应用内页面导航，并非 Chrome 的新标签页。当前版本内屏采用目录＋正文，不是微信读书双页横向翻页。暂不包含高亮批注、跨设备同步、整刊后台下载、音视频播放器、铰链姿态专用模式或同时驱动内外两块屏幕。

## 3. 用户流程

1. 安装 APK，打开“财新折叠屏阅读器”，进入周刊书架。
2. 设置 → 在应用内登录财新。在财新自己的网页输入账号、密码或短信验证码，成功后点底部“返回阅读”。
3. 选择一期周刊、选择文章。后台 WebView 读取网页，阅读界面呈现净化正文，不弹出新的浏览器窗口。
4. 自动尝试“余下全文”。界面显示完整性判断、配图数量及读取耗时。
5. 折叠或展开设备，继续阅读同一段。返回可回到之前目录。
6. 设置中可调整配色、字号，清除缓存，或退出登录并清除本机内容。

验证码由用户在官网页面手动输入。微信、支付宝等外部应用授权跳转尚不支持；优先使用财新账号／手机号登录。官网验证码、设备风控、订阅类型、会话到期可能影响读取，届时提示重新登录或查看原文。不能把“Cookie 已保存”当作“付费全文已验证”。

## 4. 折叠屏交互与状态连续性

- 窗口宽度小于 700 CSS px：文章单栏，充分利用外屏宽度；图片等比例缩放。
- 窗口宽度至少 700 CSS px：左侧章节目录，右侧正文；更宽窗口适当增加留白。
- 屏幕尺寸、方向、密度变化由同一 Activity 接收；不主动销毁阅读 WebView、不重新发起文章网络请求。
- 保存文章 URL、返回栈、段落编号和视口内偏移。布局变化后恢复逻辑阅读位置，避免简单保存旧的滚动像素。
- 退出后台及阅读滚动后保存状态；进程被系统回收后尝试恢复页面和位置，完整缓存可避免重新联网读取正文。
- 不强制方向，支持横竖屏和分屏。系统是否在合盖后立即点亮外屏，取决于 OriginOS 的应用接续设置；应用不能绕过锁屏或强制点亮显示屏。

Android 官方要求在折叠、旋转与窗口尺寸变化后保留上下文和用户状态，本设计采用自适应布局和显式状态保存。[配置变化与连续性](https://developer.android.com/guide/topics/large-screens/configuration-and-continuity)

## 5. 正文完整性与图片

只沿官网提供的同域、同文章 ID 分页链接加载，不拼造解锁地址。第一段、全文页面和后续分页合并时，处理前缀重叠与分页重复头图。对比已识别章节和正文结束标识。

状态分为：

- **完整**：章节与结束条件满足，允许写入正文缓存。
- **部分／未核实**：已读取正文，但分页或完整性条件尚不满足，明确提示对照原文。
- **受限**：官网仍显示登录或订阅墙，提示在应用内登录，不冒充全文。

图片按文中顺序保留图注与来源，支持原站懒加载属性。图片通过 HTTPS 请求并复用应用会话，保存在应用私有目录。离线仅能显示此前实际加载并缓存过的图片，不承诺首次打开即下载整篇所有图片。未识别格式或非财新域图片会加载失败，需要后续按真实样本扩展支持。

付费验收样文：

- `https://weekly.caixin.com/2026-08-21/102476335.html`：核对 DayOne、微软等配图、图注、全文顺序。
- `https://weekly.caixin.com/2026-09-04/102481858.html`：核对章节、余下全文、末段及配图。

具体图片数量和段落数量以验收当天官网、当前账号返回为准，不使用静态假正文替代在线验证。

## 6. 架构、性能和缓存

Java Activity + Android System WebView；阅读 UI 为 APK 内置 HTML/CSS/JS。一个远程 WebView 负责官网渲染和登录，一个本地 WebView 负责阅读界面。通过 evaluateJavascript 获取结构化正文；远程页面没有原生 JavaScript 桥。只有内置界面能调用受限的原生读取接口。

手机不捆绑 Chromium／Playwright，不需要 Node 服务。1.0 采用“后台 WebView 读取正文＋HTTP 下载图片＋本机缓存”。完整的原生 HTTP 正文快速通路尚未实现，不把桌面版的测速结果当成手机版结果。

缓存命中时跳过官网加载；图片与正文展示解耦。首读轮询正文就绪，默认约 300ms 一次；缺少结束标记时有短暂稳定性等待，登录墙最多等待约 7 秒后报告受限，总超时 45 秒。这些等待是待测量和优化的性能成本。

性能验收指标：缓存完整正文可读时间 P95 ≤1秒；首次读取分别记录官网响应、鉴权／脚本、分页、提取、界面渲染与图片加载。至少 20 次样本，区分冷启动、热 WebView、缓存命中。任何首次完整读取不足 1 秒的承诺必须以真机数据为依据。1.0 尚未完成这些统计验收。

缓存存于应用私有目录，不备份到系统云备份；按会话标识隔离。清除缓存不主动退出账号；退出登录会清除 WebView Cookie、网页存储和正文／图片缓存。默认按文件年龄淘汰，不是跨设备同步服务。

## 7. 权限与边界

只声明 INTERNET 权限；不申请短信、通讯录、相机、位置、通知、悬浮窗或外部存储权限。Android 安装时允许此 APK 来源是系统安装操作，不是应用运行时权限。

应用内 WebView 会话独立于手机 Chrome，无法直接复用桌面 Chrome 扩展。首次需要在应用内登录。财新可能限制并发设备或使旧会话失效；实际账号限制以官网执行为准。没有手机设备和账号交互验证，不能保证所有第三方登录方式可用。

明文 HTTP 禁用，主导航限财新 HTTPS 域；本地阅读界面限制脚本、图片来源，不向财新页面注入原生桥。Cookie 不写入报告、日志、APK 或源码。签名密钥保存在开发电脑独立目录，不打包进应用。缓存采用系统应用沙箱，未额外实现应用层加密。
