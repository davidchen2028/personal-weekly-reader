# 文章详情性能 Profile 与优化

日期：2026-09-19。目标为全文读取低于 1 秒；本轮尚未全面达标。以下为同机同会话顺序样本的单次计时，不是 P95，不代表所有网络环境。

## 基线定位

| 阶段 | AI基建 | 新教育学堂 |
| --- | ---: | ---: |
| 创建/恢复浏览器上下文 | 581 ms | 0 ms |
| 首个 HTTP 请求 | 204 ms | 131 ms |
| 网页导航至 DOMContentLoaded | 2756 ms | 6377 ms |
| 初始正文就绪等待 | 600 ms | 519 ms |
| 全文展开 | 1533 ms | 1493 ms |
| 配图核对和二次快照 | 283 ms | 271 ms |
| 后台总耗时 | 6601 ms | 8970 ms |

还有页面创建、解析和快照成本，总耗时并非只有网络请求。旧界面每 450 ms 查询一次任务，会在服务端完成后额外延迟最多约 450 ms；图片传输与页面绘制另计。

网络追踪发现，一次正文鉴权请求耗时 437 ms，但直到导航约 1.7 秒后才开始，完整页面还依次装载脚本、帐号状态、正文权限和全文页。首 HTML 返回并不包含可直接使用的已鉴权全文。

## 已实施

- 给读取链路加入 queue、browserContext、initialHttp、navigation、settle、expandAll、snapshot 等阶段计时，结果返回 timings。
- 导航在响应提交后开始等待明确的正文信号，不等待整页 DOMContentLoaded；移除额外固定 250 ms 稳定等待，仍保留网站权限、章节和结束信号检查。
- 后台阻止图片、字体、音视频、子框架和已识别的广告/音频/评论资源。图片由阅读器按原地址加载，避免在读取浏览器中再下载一遍。
- 图片已有真实地址时不逐张滚动，仍为缺少地址的懒加载图片保留滚动补齐。
- 对实际发现的“余下全文”链接直接导航；脚本按钮仍正常点击。
- 成功读取后在当前会话内记住已核验的全文 URL 和章节清单，下次强制刷新可直接进入该地址，不猜测全文 URL，不缓存鉴权结论。会话更换后不复用旧入口记录，最多保留 500 项。
- 前端任务查询间隔由 450 ms 改为 100 ms。缓存命中不经过轮询。
- 周刊目录的文章链接使用新标签页，附带本期信息，新页面可返回本期目录。

## 最新结果

| 场景 | AI基建 | 新教育学堂 |
| --- | ---: | ---: |
| 本轮首次全文（AI 含浏览器启动） | 2921 ms | 1651 ms |
| 已知全文入口，再向财新重新读取，非正文缓存 | 840 ms | 1059 ms |
| 正文内容缓存 | 上轮本地接口约 2 ms | 上轮本地接口约 2 ms |

详情见 `profile-after.jsonl`。两篇均为 complete，分别 107/163 个块，均有 6 张图片；规范化正文顺序校验值保持 -2086332321 / -1188378878，与此前原文核验一致。15 项自动测试通过。

这些数字是后端返回结构化全文的时间，不含图片全部下载、浏览器冷启动页面文件和绘制，不应当称为“整页 1 秒加载”。首次未缓存全文仍未达成 1 秒目标。后续若要更接近稳定首开 1 秒，需要继续验证可直接授权获取全文的 HTTP 路径，或在用户明确选择后提前读取；不能靠省略鉴权、只取第一页或把缓存成绩混作首次成绩。

## 复现

- `node scripts/profile.mjs`：读取两篇样本，再次读取已验证全文入口，输出各阶段时间与正文校验值，不输出正文或 Cookie。
- `node scripts/network-profile.mjs`：正常加载样本到全文入口出现，记录已完成请求的类型、耗时和不含查询串的地址，数字标识脱敏。
- `npm test`：解析与接口回归。

## 仍需注意

会话同步目前按全部 Cookie 内容变化保守失效，跟踪 Cookie 更新也可能使缓存无法复用。该行为可能解释部分重复打开仍慢的体验，但本轮没有将未经验证的 Cookie 排除在会话隔离之外。完整首屏计时、更多样本的中位数/P95、登录失效和异常分页性能仍需后续验证。
