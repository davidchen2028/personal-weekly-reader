# PC 周刊阅读器：《财经》杂志接入设计

日期：2026-09-27　版本：讨论稿 v1　状态：用户已确认并授权实施。

## 1. 目标与范围

在现有财新、经济观察报阅读器中加入《财经》，统一使用刊物选择器、年份下拉框、期刊目录、文章阅读页及本机缓存。保留现有两刊数据与操作方式。本轮仅 PC Web，不包含 Android APK 升级。

已确认：日常 Chrome 同步登录态；缓存正文及全部文章配图；PDF／整刊文件仅保留官网实际提供的入口，不推测下载链接。常规期刊和增刊均接入。用户确认账号已购买权限，可阅读全文；实现后仍需在同步会话中做实际对照验收。

已确认：三刊分别首次同步、每 6 小时检查；“全部缓存”仅作用于当前刊物。

## 2. 已核验的官网结构

以下为未登录的公开页面与官网自身请求，尚未验证用户付费会话。

| 功能 | 来源与实测结果 |
| --- | --- |
| 期刊列表 | https://www.mycaijing.com/issue ，页面提供 2013—2026 年份选项；年份动态发现，不写死 |
| 年份分页 | 页面脚本使用 POST `/issue/ajax-list?year=2026&type=0&page=1`；实测 2026、2025 返回 JSON，含 `data.data`、`current_page`、`last_page`、`next_page_url`、`total` |
| 列表字段 | `id`、`year`、`issueNumber`、`totalIssueNumber`、`title`、`issueDate`、`coverImagePath`；1121 是内部 ID，752 是总期号，不可混用 |
| 期刊目录 | https://www.mycaijing.com/issue/detail/1121 ，包含 33 个真实文章链接（排除脚本模板）；保留栏目与原始顺序 |
| 示例文章 | https://www.mycaijing.com/article/detail/581400?source_id=43 ，未登录 `.article-content` 仅约 184 字，并出现购买界面，不能当成全文 |
| 图片 | 当前观察到 `res.caijingmobile.com`，与主站域不同，需独立图片白名单 |
| 增刊 | 官网有 `/issue?type=1` 入口，与常规刊 `type=0` 分开 |

注意：未登录页面其他容器、脚本及结构化数据可能含额外文字；不据此判定付费权限或拼凑全文。登录后的正文容器、权限标志及图片数量需要对照官网实际可读内容核实。

## 3. 用户体验

刊物选择器新增“财经杂志”，内部 provider 使用 `caijing`，与 `caixin` 明确区分。选择后只显示该刊书架、年份、同步状态和缓存统计；刷新、浏览器前进后退及文章新标签页均保留 provider。

书架按出版日期倒序，展示封面、标题、出版日期和总期号；增加“全部／常规期刊／增刊”筛选，增刊显示独立标记。增刊缺少总期号时使用官网名称，不编造期号。目录保留官网栏目与文章顺序；点击文章打开新标签页。阅读页沿用字号、主题、阅读进度与图片展示，清除广告、推荐、支付控件，保留署名、图注和原文入口。

账号界面区分“已配对”“登录态已同步”“需要登录”“当前文章无订阅权限”和“正文完整性待核验”。收到 Cookie 并不代表已核实订阅权益。

## 4. 接入架构与改动点

| 模块 | 计划改动 |
| --- | --- |
| `providers/caijing.mjs`（新增） | URL 校验、年份与列表分页、目录解析、正文提取、权限/完整性判断、图片收集 |
| `server.mjs` | 注册第三刊；逐步将双刊条件分支替换为 provider 配置，保持财新原有默认路由兼容 |
| `lib/session.mjs` | 复用会话持久化、无头浏览器、空名称 Cookie 兼容；按刊隔离 |
| `lib/cache.mjs` / `lib/library-sync.mjs` | 复用完成清单、图片校验、断点恢复；落实下述会话刷新与缓存复用规则 |
| `extension/*` | 新增财经选择项、可选站点权限、Cookie 变更监听和独立同步状态 |
| `public/*` | 新增品牌文案、选择项、刊物上下文及分刊统计；尽量改为配置驱动 |
| `tests/*` | 添加财经解析夹具与三刊隔离/回归测试 |

数据目录使用现有数据根目录下 `providers/caijing/`。目录、正文、图片、任务进度分别隔离；不搬迁现有财新与经济观察报文件。

文章身份使用 `caijing + source_id + articleId`，访问官网时保留 `source_id`。期刊与文章采用关联关系，同一文章可属于多期，避免重复缓存。剔除已确认无关的跟踪参数，不随意删减影响内容或权限的参数。

## 5. 登录与 Chrome 扩展

沿用本机配对凭证，不要求用户重新为第三刊配对。用户选择财经并点击同步时，按需申请 `https://*.mycaijing.com/*` 权限；仅导出该刊相关 Cookie 至已配对的本机服务。保留 HttpOnly、Secure、SameSite、有效期和空名称 Cookie；不得同步其他刊物 Cookie 到财经请求。

首版优先验证 Cookie 是否足够。若实际登录依赖额外域或 localStorage，记录具体证据后补充设计并由用户授权，不默认读取全部浏览器存储。图片域不因资源加载而获得账号 Cookie。

账号会话存本机受限文件，不写入源码、日志和 Git。断开财经不影响另两刊；清除缓存和清除会话分别提供入口。

## 6. 获取流程与性能

1. 读取本机完整缓存；命中时直接呈现。
2. 未命中时复用已有会话，通过 HTTP 请求官网列表、目录或正文，避免每次启动浏览器和等待广告。
3. 仅当正常页面确需 JavaScript 渲染或登录验证时使用复用的无头 Chrome 上下文，按正文/权限就绪条件等待，避免固定睡眠和全页 network-idle。
4. 自动展开官网确实提供的全文入口；有真实分页则只合并同篇文章，去除分页重叠，不抓取推荐文章。
5. 验证权限及正文完整性，再保存有序段落、标题、图片和图注。图片支持 src、srcset、懒加载属性；按官网实际顺序抽取，不误删正文中重复出现的图。

性能验收：记录 cache lookup、HTTP、浏览器回退、解析、图片及总耗时；本机完整缓存点击到正文可见目标小于 1 秒。未缓存 HTTP 路径争取 1 秒以内，但实测报告分开列出冷启动和网络延迟，不承诺所有首次请求在 1 秒内。图片异步显示，不阻塞文字首屏；缓存完成则必须等待必要图片成功。

## 7. 缓存及定时同步

建议三刊独立执行：首次连接后建立该刊目录并同步；每 6 小时检查新期刊。“全部缓存”遍历当前刊物所有已发现年份、所有列表分页、所有期刊和文章，支持暂停、恢复、失败重试及进度显示。常规期刊 type=0 与增刊 type=1 分别发现年份、分页抓取，再按官网 ID 合并去重；增刊缺少年份时由可靠出版日期归档，无可靠日期则列为“年份待确认”。“全部缓存”覆盖当前刊物两种类型，不因可见年份或类型筛选缩小范围。年份与类型分别持久化分页游标；根据官网分页终点停止，同时防循环。

以完成清单记录文章身份、正文摘要校验值、图片列表/校验值、所属期刊及完成时间。完整正文与全部必要图片成功落盘后才标记完成。下次任务先检查清单，成功项跳过；缺图只补图片，失败项重试。预览、付费墙、未知完整性以及仅有空正文不能标记成功。

会话刷新不能简单等同于账号切换：现有系统 Cookie 内容变更会更新缓存 namespace，可能造成重复下载。本次接入需显式处理此边界：若官网存在可验证稳定账号标识，以本机散列账号标识隔离存档、会话 revision 管理请求；常规令牌刷新不改变存档归属。如果无法验证账号身份，不跨身份猜测复用付费缓存，界面明确提示重新核验，而不能承诺跨所有 Cookie 变化永远跳过。禁止把 Cookie 值本身作为长期账号标识。

遇登录过期暂停该刊并提示同步；单篇/旧刊无权限记录原因并继续其他可读条目；429 按 Retry-After 退避，不密集请求。复用全局并发限制，交互阅读优先于后台任务。

6 小时定时任务运行在本机阅读器服务内：Mac 关机、休眠或服务关闭期间不执行，恢复后按上次检查时间补查，不依赖聊天自动化。

## 8. 实施顺序及验收

确认需求 → 注册第三刊和扩展权限 → 列表/目录与年份分页 → 已登录正文/全图验证 → 缓存和独立调度 → 三刊回归。

验收至少包括：

- 常规期刊和增刊两条列表完整读取，增刊无总期号及跨类型重复条目正确处理。
- 财经 2026 与 2025 跨年切换，多页年份不漏刊；1121 内部 ID 与总第752期展示正确。
- 第1121期目录与官网逐项比对；样例581400全文、末段、全部图片和图注对照已登录官网。
- 普通文章、付费文章、旧刊、无权限及登录过期分别测试；失败不会产生“已完整缓存”。
- 全部缓存第二次执行不重新下载已完成正文与图片；中断重启可恢复；缺图补齐；自动检查只影响当前刊任务。
- 三刊登录/缓存/暂停/断开互不串用；旧财新链接兼容；新标签页 provider 正确。
- 缓存读取延迟与首次抓取延迟分别给出实测结果。

本设计不包含绕过订阅权限、PDF批量下载或手机端升级。下一阶段实施前需用户确认本文及待确认项。
