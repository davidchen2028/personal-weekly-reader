版本：v0.1（待确认）  
日期：2026-09-27  
范围：本地 PC Web 阅读器、Chrome 扩展、缓存与同步服务

## 1. 目标与已确认范围

在同一个 `http://127.0.0.1:4317` 阅读器内，通过「财新 / 经济观察报」选择器切换刊物。保留现有书架、年份筛选、分组目录、文章新标签页、阅读配色、字号、配图放大及本机缓存体验。

用户已确认：

- 经济观察报只缓存文字正文与文章配图；PDF／整版电子报保留原站入口，不后台下载。
- 「全部缓存」、暂停、重试、清除只作用于当前选中的刊物。
- 两刊各自首次同步，之后分别每 12 小时检查新刊。切换界面不停止另一刊物的任务。
- 复用 Chrome 扩展同步登录态的方式；两刊 Cookie、账号、缓存和错误状态相互隔离。
- 下载成功必须有持久化记录，下次任务直接跳过，不重新请求已成功文章和配图。

本轮不改 Android APK，不部署云服务，不要求账号密码发给开发者。月费是用户提供的订阅背景，不写死为程序的权限判断条件。

## 2. 调研结果：已确认与待验证

本次以只读方式检查官网 HTML、官网前端脚本及一期接口的数据结构，未导入经济观察报登录 Cookie。用户给出的首页链接末尾夹有中文左括号，已按实际地址去掉该标点。

| 项目 | 观察结果 | 设计影响 |
|---|---|---|
| 期刊首页 | `/epaper/eeocover/1.shtml` 为服务端列表，单期包含 `e_cid_*` 期号、`e_cbqh_*` 日期、封面及电子／文字／PDF入口 | 优先 HTTP 解析，无需打开可见浏览器 |
| 历史列表 | 首页有真实“下一页”和尾页链接；本次显示尾页 59。第一页观察到 20 期，末页 13 期 | 沿分页链接遍历，不能照搬财新“首页包含全部隐藏期刊”的假设；不把 59 写死 |
| 年份 | 每期有发行日期 | 按发行日期年份筛选，而不是按抓取年份或文章日期 |
| 期刊页面 | `index.html?qid=1289` 的 HTML 是动态容器 | 静态 HTML 不能直接给出目录／全文 |
| 目录与正文 | 官网 `js/index.js` 调用 `getEpaper`，使用 `data.list[].article_list[]` 同时呈现版面与文章 | 一期请求可能已经返回整期正文；按期获取一次，再拆分成文章 |
| 文章切换 | 前端调用 `article(i,j)`，URL 不随文章切换 | 不能用同一个 qid URL 作为所有文章的缓存键 |
| 1289 期结构 | 本次结构检查为 24 个版面、37 个文章条目；37 个条目都有 `id`，13 个条目有 `imagesname` | 可使用期号＋文章 ID；仍需核验 ID 唯一性与跨版重复关系 |
| 图片 | `imagesname` 是逗号分隔文件名，前端与 `uri` 拼接；观察到图片在 epaper.eeo.com.cn | 需提取全部文件名，并保留官网展示顺序 |
| 正文元数据 | `title`、`authorName`、`publishTime`、`number`、`content` | 无需从截图 OCR；按字段构造阅读页面 |
| 鉴权 | 脚本区分 usertype=1（登录）、3（购买）；本次匿名响应却出现布尔 false，同时有结构化 data | 不能把 false 当作已登录／已购，也不能依据一次响应推断订阅规则；实施时用用户实际会话验证 |

结构计数是当前样本观察值，不是长期硬编码断言，也不意味着全部历史刊物均采用相同结构或已确认可读。

## 3. 用户界面

### 3.1 刊物选择器

页头提供「财新」「经济观察报」选择器，记住上次选择。财新继续使用现有深绿色，经济观察报可使用克制的暗红色品牌点缀；正文主题、字号、行宽和双栏设置保持共用。

切换后更新书架、年份列表、页头刊名、连接状态、缓存任务状态及全部文案，不出现经济观察报页面仍写“财新账号”的情况。每个标签页的刊物以 URL 路由为准，不能被另一个标签页的选择覆盖。

书架：经济观察报封面采用完整显示，不用裁切方式强行套用财新封面比例；显示刊名、期号、发行日期。目录按「第01版 要闻」「第02版 新闻」等原版面顺序分组。

文章卡片仍在新标签页打开。文章页保留标题、作者、日期、版次、正文、图片与图注，提供返回本期目录和原站入口。官网不支持精确文章深链时，“原文”明确打开所在期，不能伪称可定位某篇。

### 3.2 缓存与连接文案

按钮根据当前选择显示「全部缓存 · 经济观察报」等明确目标。任务面板显示：期刊发现进度、目录总量、成功文章数、已跳过成功项、正文成功但缺图数、待核验数、失败数、当前项目、最近检查、下次检查。

连接面板同时列出两刊各自的“未连接／已同步待验证／可读／登录失效／订阅不足”。Cookie 数量不等于订阅验证成功。不要把单篇订阅不足误报成另一刊账号失效。

## 4. 服务端架构：共用流程，分离刊物适配

保留 Express、现有前端、Playwright 无头 Chrome、HTTP 客户端和本机文件缓存。增加 provider 注册表，统一生命周期，但不把财新解析规则直接泛化为经济观察报规则。

建议模块职责：

| 模块 | 职责 |
|---|---|
| `providers/registry.mjs` | `caixin` / `eeo` 元数据、域名白名单、适配器 |
| `providers/caixin.mjs` | 包装现有财新列表、目录、分页全文提取，先保持行为不变 |
| `providers/eeo.mjs` | 历史列表分页、一期数据获取、版面目录、文章及配图规范化 |
| `lib/session.mjs` | 按刊物维护 Cookie、账号身份、会话版本和浏览器上下文 |
| `lib/library-sync.mjs` | 每刊独立调度、队列、重试、进度；共用全局并发预算 |
| `lib/download-manifest.mjs` | 文章和资源成功记录、校验、恢复与去重 |
| `server.mjs` | API 路由、provider 校验、连接鉴权、内容与图片输出 |
| `public/*` | 刊物选择器、品牌文案、分刊任务和既有阅读组件 |

适配器契约（设计，不是本轮代码）：

- `discoverIssues(cursor, signal)`：一页期刊＋下一页游标；支持增量发现。
- `fetchIssue(issueId, session, signal)`：版面目录，必要时连同整期正文快照。
- `resolveArticle(articleRef, issueSnapshot, session, signal)`：输出统一文章 blocks；经济观察报优先从已有一期快照取值。
- `assessAccess(response, session)`：区分未登录、单篇无权限、受限、结构错误、可读和待核验。
- `extractAssets(article)`：全部图片及来源顺序。

HTTP 优先，无头浏览器作为正常网站脚本／鉴权流程的兼容路径，不启动可见浏览器窗口。不得改写官网权限字段或忽略登录／购买状态。官网接口参数从已观察的前端行为得出，但不是稳定公开 API，需封装在适配器内并有失败降级。

## 5. 经济观察报读取流程

### 5.1 期刊发现

从真实首页开始，逐页跟随“下一页”；对官网输出的旧 HTTP 列表链接仅在同一已允许域、相同路径可使用 HTTPS 时升级协议，不扩大到任意站点。校验循环、重复 URL、空页面和错误页面。页面数设可配置防失控上限，超过上限显示“发现未完成”，不能当成全量完成。

每处理一页原子保存游标和已发现期号，进程中断后可恢复。以 `provider + qid` 去重，日期与封面为元数据，不根据最新期号倒推／猜测全部历史 ID。官网已展示但日期在未来的期刊仍可列出，阅读权限以实际返回为准。

首次遍历全部实际可发现历史页；每6小时从首页开始检查至稳定的已知边界。历史发现未完成时继续补齐历史游标。另保留“重新扫描全部目录”入口，以发现补录到旧分页的期刊；定时增量不能宣称发现所有历史页的任意改动。

### 5.2 一期获取与拆分

一次请求第1289期授权数据 → 校验期号与结构 → 遍历所有版面 → 输出目录和文章列表 → 按文章建立存档任务。HTTP 响应已含整期正文时，不为37个条目重复请求37次一期接口。

无头回退也按期复用一次页面／网络响应，不能为每篇文章重新启动 Chrome。相同刊物＋账号＋期号的并发请求合并为同一个任务。必要时读取网站正常渲染后的数据，仍须确认官网实际允许展示。

### 5.3 文章唯一身份

优先键：`eeo / qid / article.id`。文章同时出现在不同版面时保留目录引用关系，不仅按标题去重；相同 ID 且内容一致才共享一份文章，若同 ID 内容冲突则保留版次变体并记录结构告警。

老刊缺少 ID 时使用持久化映射：期号＋版次＋标题／作者特征＋冲突序号，正文哈希是版本标识，不是唯一身份。歧义时不静默合并两个条目。

浏览器本地文章路由可表示为 `#eeo/article/1289/<articleId>`，目录为 `#eeo/issue/1289`。这一地址是阅读器内部路由，不当作官网地址请求。

### 5.4 正文、图片与完整性

正文按官网换行语义形成段落，移除脚本和不可执行元素，去除与作者字段完全重复的首行署名。小标题仅在原数据有可靠结构时标识，不靠猜测截断或重排正文。

提取 `imagesname` 全部文件名，按官网前端顺序展示；合并正文中实际存在的内嵌图片，避免重复。只有来源确实提供图注／来源时才显示，不编造图注。图片链接、重定向和 MIME 类型均经过 provider 白名单检查。

经济观察报不沿用财新“■末尾标记”规则。完成判定基于：实际授权响应／页面可读、有效文章结构、未命中预览／截断／登录提示，且正文条目和媒体清单能与官网渲染对应。单纯 HTTP200、state=true 或 usertype=false 均不足以单独证明付费全文。

纯广告／空正文＋图片的条目保留版面与标题，并识别为图像条目，不伪造文字。广告条目不静默删除，完成统计区分正文文章与图像条目；PDF和整版图不纳入本轮资源清单。

## 6. Chrome 扩展与会话隔离

保留一个扩展、一次本机配对，增加两刊单独同步和状态。旧版本扩展不带 provider 的请求继续解释为财新，避免升级瞬间破坏已有使用。

新增经济观察报域权限需要用户在 Chrome 扩展管理页重新加载并接受权限变化。可采用按需站点权限，在“连接经济观察报”时请求；若实现使用静态 host_permissions，安装说明明确新增域。财新的权限不扩大到其他网站。

初步涉及的官网域：www.eeo.com.cn、epaper.eeo.com.cn、api.eeo.com.cn、app.eeo.com.cn、img.eeo.com.cn、upload.eeo.com.cn。Cookie 枚举按 eeo.com.cn 域树过滤；内容与资源请求按用途限制至已核验的主机。仅因截图或网页提到某域，不自动信任该域。

协议示例：同步请求包含 `{provider: "eeo", cookies: [...]}`。服务端再次检查 Cookie 域属于目标刊物；目标是 eeo 时拒绝 caixin Cookie。分开保存版本号、账号范围、浏览器上下文与失效状态；断开经济观察报不能销毁财新任务或登录。

当前证据显示官网使用 Cookie 型登录流程，但尚未以用户实际会话完成验证。若实际需要 localStorage 等额外令牌，先说明缺少的字段与来源，再扩展最小权限；不默认读取整个 Chrome 存储，也不要求用户上传密码。

账号缓存范围优先使用经过正常账号响应确认的稳定用户标识，禁止把所有匿名状态映射到一个公共付费缓存范围。无法验证账号身份时保守隔离，提示可能需重新同步；不可为避免重复下载而混用两个人的缓存。

## 7. 持久化成功记录：本次关键改动

现有同步器主要靠正文 `access=complete` 和文件存在跳过，还会遍历图片并计数；它没有将“全文＋所有图片成功”作为独立、可查询的持久化状态。本次增加文章级 manifest，避免把每次运行临时计数当成下载记录。

建议延续现有文件存储：每篇文章一个 manifest，以临时文件写入＋rename 原子提交；刊物汇总索引可重建，不作为唯一事实来源。所有同键任务合并，写入串行化。不在本轮引入数据库服务器。

记录至少包含：

| 字段 | 用途 |
|---|---|
| provider、accountScope、issueId、articleId | 唯一身份及账号隔离 |
| articleStatus、bodyStatus、mediaStatus | 区分正文成功、缺图、全部成功等 |
| contentHash、sourceRevision（若有）、parserVersion | 内容版本与解析版本 |
| articleFile、bytes、checksum | 正文文件完整性 |
| assets[]：sourceUrl、localFile、type、bytes、checksum、status | 每张图片可独立补齐 |
| completedAt、lastAttemptAt、attemptCount、nextRetryAt、errorCode | 重试与成功时间 |

状态：`pending → fetching → body_ready → media_pending → complete`；另有 `unverified`、`restricted`、`failed`、`interrupted`、图像条目状态。

“直接跳过成功文章”精确定义：当前刊物＋账号＋文章键一致，manifest=complete，正文和清单全部资源存在且大小匹配，解析版本兼容。命中后只检查本地记录和文件，不请求该文章或图片。摘要校验用于写入、恢复异常或主动完整性检查，不每6小时重复哈希所有历史大文件。

- 正文已成功但缺一张图：只补缺图，不重取正文。
- 进程在下载中断电：未原子提交 complete 的任务重排，已完成资源复用。
- manifest 成功但文件缺失／损坏：降级为待补齐，不假装成功。
- 成功正文更新失败：保留旧成功版本，另记刷新错误。
- 官网一期响应本身包含整期正文时，发现新目录可能不可避免接收已有文章字段；解析后比较记录并跳过重写及配图下载，不能声称连这些响应字节也完全没有接收。
- 普通同步不反复验证旧成功正文是否被官网修订；“刷新本文／重抓本期”可强制获取。若新响应提供明确内容版本变化，再更新该版本。

## 8. 调度、失败与容量

每刊独立记录 enabled、lastCheck、nextCheck、历史游标与任务状态。首次连接验证可用后开始；之后6小时一轮，服务重启／电脑休眠后补做过期检查。服务不运行时无法自动下载，不额外建立 Codex 定时任务。

共用全局最多2个网络／读取任务预算，后台初始每刊串行；前台阅读优先。支持取消、超时、退避，尊重429的 Retry-After。新刊优先于剩余历史队列；单刊失败不影响另一刊。

区分错误：

- 明确登录失效：暂停该刊等待重新同步。
- 确认仅一篇／一期无订阅权限：记录受限并继续其他可读项目，不无限重试。
- 401/403 或鉴权含义不明：先暂停该刊并提示核验，不能擅自认作已授权。
- 429：按服务器要求冷却该刊，不误标“账号过期”。
- 网络／图片失败：有限次数重试，之后延迟到下一轮；成功记录不回退。
- 结构变化：保留可读内容为待核验，不标 complete。

长期存档沿用用户已选择的“不按30天／1GB淘汰”；按刊物显示磁盘占用，清除操作限定当前刊物。磁盘不足时停止写入并提示，不删除另一刊或旧成功正文腾空间。

## 9. API、路由与旧数据兼容

推荐新增 provider 参数但保留旧接口默认财新：

- `GET /api/providers`：刊物列表、品牌文案和连接能力。
- `GET /api/issues?provider=eeo&year=2026`：期刊书架。
- `GET /api/issue?provider=eeo&issueId=1289`：版面目录。
- `POST /api/read`：`{provider, issueId, articleId, refresh}`；旧财新 `{url}` 仍可用。
- `/api/library/status|start|pause|clear`：必须明确当前 provider；旧调用默认财新。
- `/api/bridge/sync`：provider＋本地配对令牌；会话不回传前端。
- 图片 API 的本地资源键包含 provider／账号范围，不能拿财新键读取经济观察报资源。

建议数据根目录保持 `CaixinReader/v2`，新增 `providers/eeo`，既有财新文件暂时原位使用；避免一次升级搬移大量缓存或令原配对失效。刊物和账号范围写入元数据及资源键。

旧财新 `#issue/<url>`、`#article/<url>` 链接仍能打开。新路由显式包含 provider。迁移扫描旧成功正文，只有全部图片文件核验存在才生成 complete manifest；否则记为 body_ready 并补图。迁移不重复下载已存在的合格资源、不删除原文件，可回滚。

对所有正文、标题、错误信息做显示转义；不执行远程 HTML 的脚本。请求继续保留 Host／Origin／配对令牌校验、URL和重定向校验。会话不入 GitHub、日志、设计文档或前端存储。

## 10. 实施顺序与验收

1. 提取 provider 注册表，接入现有财新适配器；旧链接、阅读、缓存与扩展全部回归。

3. 实现经济观察报历史分页、目录／文章结构化输出，完成选择器和文案。

## 11. 请确认的设计结论

本方案采用“统一阅读器＋两刊适配器”，不另起第二个网站；经济观察报按期获取数据、按文章记录完成状态。已确认的缓存范围与按钮作用域已写入第1节。
